## Context

现有 Runtime 0.4.0 已具备本机回环服务、Codex/Claude Provider、嘉立创EDA Bridge 发现、原理图固定命令、源码快照、绑定批准、回读、官方 DRC 与回滚。生产级 PCBA 环境需要把同样的安全模型扩展到 PCB，同时处理 PCB 图元数量大、网络拓扑复杂、官方自动布局/布线能力有限、导出具有生产后果等问题。

## Goals / Non-Goals

**Goals:**

- Codex 通过版本化工具而非任意脚本完成从需求到生产资料的 PCBA 工作流。
- PCB 写入具备目标绑定、快照、逐步回读、官方 DRC、失败回滚和完整审计。
- 支持板框、规则、布局、走线、过孔、铺铜、丝印及生产资料生成。
- 当前 CH32V003 工程成为首个真实端到端验收样板，但能力不绑定单一器件或单一工程。

**Non-Goals:**

- 不自动下单、支付、接受商业条款或删除工程。
- 不允许 Codex 直接向 Bridge 提交任意 JavaScript。
- 不把自定义几何检查冒充嘉立创EDA官方 DRC/DFM。
- 不承诺在缺少机械、电气或器件证据时自动补猜设计事实。

## Decisions

1. **固定命令注册表而非通用执行器。** PCB 能力按读取、创建、修改、验证、导出拆成严格参数 Schema；任意代码端点仅属于底层 Bridge，不暴露给 Codex。替代方案是让模型生成脚本，因无法可靠限制权限和审计而拒绝。
2. **两级计划。** Codex 先生成语义设计计划，再由确定性编译器生成坐标、层、网络、线宽与图元操作；只有编译产物可以审批执行。这样将工程判断与 API 细节分离。
3. **阶段性事务。** PCB 执行分为同步、板框/规则、布局、布线/过孔、铺铜/丝印、验证、导出。每阶段建立源码摘要和对象清单；失败恢复到该阶段前快照并锁定后续阶段。
4. **官方检查为硬门禁。** 网表一致性、封装、PCB DRC 和适用的 3D/DFM 检查必须使用嘉立创EDA正式结果；任何错误或未知结果阻断完成与生产导出。
5. **人工审批分级。** 读取无需批准；设计批量写入需要绑定计划批准；BOM/CPL/Gerber 导出需要独立批准；下单与支付始终不可用。
6. **可重复验收夹具。** CH32V003 样板固定为 45×30mm、2层、1.6mm、1oz、无安装孔和已确认接口位置，用于验证工具链，不把其约束作为其他项目默认值。
7. **本地优先。** Runtime 仅监听回环地址，Provider 密钥留在 macOS 钥匙串，文档源码不进入普通日志或模型上下文，只传递规范化摘要和必要证据。

## Risks / Trade-offs

- [嘉立创EDA API 缺少某些自动布局/布线或导出接口] → 逐项核对正式 API；不存在的能力保持阻塞并转为用户在 EDA 内完成的受控人工步骤，不伪造完成。
- [大规模 PCB 操作超时] → 小批次阶段执行、心跳、可续传状态和阶段快照，关闭会阻塞 API 的面板。
- [自动布线电气上通过但工程质量差] → 规则驱动、关键网络优先、回流路径检查、人工布局评审和明确质量指标。
- [库器件或封装发生变化] → 执行前重新读取库 UUID、封装、焊盘和 LCSC 身份，并绑定计划哈希。
- [导出文件存在但内容不完整] → 对 Gerber 层集、钻孔、BOM 字段和 CPL 位号集合做独立一致性检查。

## Migration Plan

1. 增加只读 PCB 模型与能力探测，不改变现有原理图流程。
2. 添加固定 PCB 写命令、参数校验和模拟测试。
3. 增加 PCB 事务执行器、审批、回读、DRC 与回滚。
4. 扩展 Codex Schema 和桌面界面。
5. 在专用工程先做快照/恢复演练，再执行 CH32V003 现场验收。
6. 只有全部硬门禁通过后开放生产资料导出；任一失败可回退到原理图完成版本。

## Open Questions

- 嘉立创EDA V3.2.175 当前公开扩展 API 对原理图转 PCB、官方自动布线、3D 干涉和 Gerber/CPL 导出的覆盖范围需要在实现阶段逐项现场探测。
- 嘉立创 DFM 与采购库存属于外部服务；若没有稳定官方 API，则先输出可验证文件并保持“待人工上传检查”状态。
