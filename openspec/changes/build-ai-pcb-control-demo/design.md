## Context

项目当前只有产品PRD和OpenSpec配置，没有应用代码、设计规范或可复用组件。用户需要一套能够在Mac桌面上完整演示的交互Demo，核心目的是验证产品信息架构、AI审批闭环和嘉立创EDA控制体验，而不是在本阶段接入真实AI、真实EDA写操作或生产系统。

Demo的主要利益相关者是个人硬件工程师和产品负责人。设计必须在没有后端、没有账号体系和没有真实硬件工程数据的条件下保持可操作、可复现和可测试，同时清楚区分模拟结果与真实工程事实。

## Goals / Non-Goals

**Goals:**

- 建立可直接启动的React + TypeScript桌面Demo。
- 覆盖PRD定义的八个主功能区，并让所有可见交互控件产生可观察结果。
- 用本地模拟服务演示从项目需求到AI计划、审批、EDA执行、验证和版本回滚的完整闭环。
- 提供统一状态、通知、确认、空状态、错误状态和结构化日志。
- 使用持久化Demo数据，使刷新页面后仍能继续当前演示。
- 为关键路径建立自动化测试和无死按钮检查。

**Non-Goals:**

- 不接入真实OpenAI、Codex或其他模型API。
- 不调用真实嘉立创EDA Bridge，不修改真实工程。
- 不实现Tauri/Rust壳层、macOS Keychain、签名、公证或DMG。
- 不生成可用于制造的真实Gerber、BOM或坐标文件。
- 不实现登录、云同步、多人协作、下单或支付。

## Decisions

### 1. 使用Vite + React + TypeScript单页应用

Demo采用Vite构建，React负责组件化界面，TypeScript负责领域模型和交互状态约束。相比纯HTML，React更适合八个功能区共享状态、弹窗和复杂任务状态机；相比直接搭建Tauri，纯前端Demo启动更快，也能先验证产品流程。

替代方案：纯HTML文件依赖少，但状态逻辑难维护；立即构建Tauri会把时间消耗在桌面打包和系统权限上，偏离本次交互验证目标。

### 2. 采用单页状态驱动导航，不引入复杂路由依赖

八个主页面由受控导航状态切换，URL Hash同步当前页面，刷新后可以恢复。Demo不需要多层公共路由和鉴权，因此不引入React Router，减少依赖并保持交互可控。

### 3. 使用集中式Reducer和可序列化领域状态

应用使用React Context + `useReducer`管理项目、需求、BOM、任务、EDA会话、验证、版本、设置和通知。所有状态转换使用明确Action，便于日志记录、持久化和自动测试。相比引入Redux或Zustand，该方案足以覆盖单用户Demo，且避免额外抽象。

### 4. 外部能力统一通过模拟适配器

AI生成、EDA连接、命令执行、验证、导出和诊断均通过`services/demoAdapter`暴露异步接口。接口返回可控延迟、成功结果和可触发错误，页面不能直接写死结果。未来真实Provider和EasyEDA Bridge可以实现同一接口而不重写页面。

每次模拟行为都显示“演示模式”，生成的文件使用Blob下载并标注`DEMO`，防止被误认为生产资料。

### 5. 视觉采用“精密工作台”工业实用风格

界面使用深石墨工作区、暖白信息面板、信号橙和电气绿作为状态色；标题使用IBM Plex Sans/Mono，中文使用明确的中文字体回退。视觉记忆点是类似示波器和工程台账的顶部状态总线、细网格背景、带编号的任务阶段和高密度但清晰的参数面板。

不使用紫色渐变、通用SaaS卡片海洋或装饰性3D插画。动画只用于页面切换、任务推进、连接脉冲和通知，不干扰工程信息阅读。

### 6. 所有交互必须归入明确行为类别

每个按钮、菜单、标签、筛选、开关和行操作必须属于以下之一：导航、编辑、状态转换、打开详情、下载演示文件、显示确认、触发模拟任务或显示明确的禁用原因。界面不保留无事件处理器的装饰性按钮。

禁用按钮必须提供`title`或附近说明；图标按钮必须提供可访问名称。

### 7. 本地持久化与安全重置

Demo状态保存到带版本号的`localStorage`键。解析失败时回退到种子数据并记录警告。设置页提供“重置演示数据”，需二次确认；重置只清理本Demo键，不影响其他站点数据。

### 8. 测试采用分层验证

- TypeScript和构建检查确保代码可编译；
- 组件/状态测试覆盖关键Reducer和任务状态机；
- Playwright覆盖八个导航、关键闭环和所有可见按钮扫描；
- 浏览器控制做最终视觉和控制台检查。

## Risks / Trade-offs

- [Demo功能丰富导致代码集中] → 按领域拆分页面、共享组件、Reducer和模拟服务，限制单文件体积。
- [“所有按钮可用”难以穷举] → 为交互元素添加稳定`data-testid`/可访问名称，并用自动化扫描点击后检查状态、弹窗、下载或导航反馈。
- [模拟行为被误认为真实执行] → 全局显示“演示模式”，EDA与AI页面重复提示，导出文件名和内容包含`DEMO`。
- [localStorage旧数据破坏新版本] → 存储键包含schema版本，读取时验证并提供重置入口。
- [高密度桌面界面在小窗口拥挤] → 以1280×800为基准，低于1100像素时折叠辅助面板，核心流程仍可用。
- [无真实API导致接口设计失真] → 所有模拟操作通过适配器和类型化领域接口，保留替换真实实现的边界。
- [中文字体在不同Mac表现不同] → 主字体随包引入IBM Plex，中文使用PingFang/Hiragino回退并验证字重。

## Migration Plan

1. 在项目根目录创建前端工程和依赖配置。
2. 建立领域类型、种子数据、Reducer、日志和本地存储。
3. 实现应用壳层和八个页面。
4. 接入模拟适配器和跨页面任务状态机。
5. 增加测试、构建和演示说明。
6. 若实现失败，可删除新增前端文件；PRD和OpenSpec产物不受影响。
