## Context

现有应用由 React 前端和仅监听本机回环地址的 Node Runtime 组成。Runtime 已能管理 Codex/Claude 配置、真实 AI 对话、日志和嘉立创EDA桥接健康检查，但桥接命令注册表只有只读命令，任务批准仍主要是前端状态，尚不能构成安全写入授权。

嘉立创EDA扩展 API 提供原理图元件、导线、网络标识、保存、文档源码以及 `sch_Drc.check`。文档源码读写和 DRC 均标注 BETA，因此 P0 必须限定在用户明确选择的专用测试工程，并保留恢复证据。用户所说的 ERC 在嘉立创EDA API 中对应原理图 DRC；界面同时展示两个名称，避免能力误解。

## Goals / Non-Goals

**Goals:**

- 建立从设计读取、信息补全、计划生成、人工审批到固定写入、保存、回读、原理图 DRC 和失败恢复的闭环。
- 让批准与实际执行内容、目标窗口和目标文档密码学绑定，阻止篡改、漂移和重放。
- 让所有写入可解释、可审计，并在任何关键验证失败时停止后续动作。
- 用 MCU、电源、LED、按键四类功能块验证 P0，但器件身份必须来自用户确认或嘉立创EDA库的精确标识。

**Non-Goals:**

- 不自动选择未确认的 MCU、电源器件、阻容值、封装或供应链料号。
- 不自动创建 PCB、布局、布线、铺铜、生成 Gerber/BOM/CPL 或下单。
- 不向浏览器、模型或外部调用方暴露通用脚本执行接口。
- 不承诺 BETA API 可用于无人值守生产工程。

## Decisions

### 1. Runtime 拥有执行权和审批权

前端只提交需求、显示计划并请求批准。Runtime 规范化计划后计算 SHA-256，签发一次性批准令牌，令牌记录计划哈希、窗口 ID、工程/文档指纹、签发时间和过期时间。执行前重新读取目标指纹并逐项比对。

替代方案是沿用前端 `approved` 状态；它无法阻止请求篡改、页面刷新或目标切换，因此不采用。

### 2. 仅使用白名单类型化命令

桥接层为每个命令定义权限、输入校验、超时和固定嘉立创EDA API 实现。写入命令仅接受精确库标识、有限坐标、连接点和网络名；Runtime 的 HTTP API 不接受 JavaScript 源码。

替代方案是把 AI 生成脚本传给 `/execute`；其权限边界过宽且难以可靠审计，因此禁止。

### 3. 源码快照优先，补偿删除作为次级保护

写入前调用 `sys_FileManager.getDocumentSource()`，把源码摘要和加密/受限保存的数据放入本地执行记录。失败时在仍为同一窗口和文档的前提下调用 `setDocumentSource()`、保存并回读摘要。执行同时记录每个新建 primitive ID，便于源码恢复失败时给出可人工审查的补偿清单，但不会静默降级为不完整恢复。

### 4. 结构化计划确定性化

AI 只负责把对话转换成符合 JSON Schema 的候选工程意图。Runtime 再执行规范化、必填项检查、坐标/网络约束检查和稳定序列化。只有所有器件都具有精确 `libraryUuid + uuid`（或经库查询解析并由用户确认的唯一身份）时才能批准。

### 5. 原理图 DRC 是最终硬门禁

写入、保存、回读成功后调用 `eda.sch_Drc.check(true, false, true)`。详细结果数组为空才通过；API 缺失、抛错或返回未知结构均为阻塞/失败，不能由自定义连通性检查替代。自定义检查仅作为更早的计划静态检查并单独命名。

### 6. 单任务串行执行

同一 Runtime 同时只允许一个写任务。每一步都持久化 append-only 事件，失败后进入 `rollback_required` 或 `rolled_back`，不得继续剩余写入。

## Risks / Trade-offs

- [嘉立创EDA源码与 DRC API 为 BETA] → 限定专用测试工程，启动前显示风险确认，保存版本与能力探测结果，并验证恢复演练后才允许执行。
- [文档源码可能包含敏感设计数据] → 只存本机，不写普通日志；日志只记录摘要、大小和快照 ID。
- [元件引脚坐标或库数据不完整] → 计划保持不可批准，要求精确器件解析和读取引脚后再生成导线。
- [用户在批准后切换窗口或编辑文档] → 执行前重读窗口和文档指纹；不一致即使令牌未过期也拒绝。
- [恢复调用失败] → 停止所有动作，记录高优先级错误、快照摘要和人工恢复说明，不声称已回滚。
- [P0 仅覆盖原理图] → UI 明确显示 PCB 设计与生产文件仍未完成。

## Migration Plan

1. 保留现有只读命令和聊天接口，新增版本化设计 API。
2. 新增数据字段时提供旧本地状态兼容默认值，不迁移或删除现有用户数据。
3. 先用 mock bridge 完成单元与集成测试，再连接一个用户确认的空白测试工程做能力探测、快照恢复演练和真实写入。
4. 若现场验证失败，关闭写入能力开关；现有聊天和只读能力继续可用。
