## 成功经验总结

1. “AI会画板”必须拆成证据读取、候选计划、确定性校验、人工批准、固定执行和独立验证，不能把模型文本直接当命令。
2. 批准必须由 Runtime 绑定计划哈希、窗口和文档源码摘要；只在前端记录 `approved` 无法防止目标漂移与重放。
3. 嘉立创EDA中用户习惯称 ERC 的能力在扩展 API 中是 `sch_Drc.check`；必须展示真实 API 名称和语义，不能以自定义连通性检查替代。
4. BETA 源码恢复必须先在空白测试工程演练，并以恢复后的 SHA-256 一致作为成功标准；调用返回 `true` 本身不够。
5. 器件精确身份和引脚坐标没有证据时保持阻塞，是比自动猜料更重要的正确性能力。
6. 嘉立创EDA保存源码会更新头部 `client`、`updateTime`、`version`；恢复验证必须忽略这些易变元数据，再比较规范化设计摘要，否则会误报回滚失败。
7. HTTP 响应脱敏与日志脱敏不能共用完全相同的字段策略；一次性批准令牌必须只返回给已认证本机调用者，同时继续从日志和错误响应中移除。
8. 嘉立创EDA会合并同网络共线导线并重建 primitive ID；可靠回读需要同时验证稳定 ID，以及保存后网络名与连续线段覆盖，不能只比较创建时 ID 或原始分段。
9. USB-C VBUS 走线不得穿过 EH 外壳接地引脚；现场回读发现的截断应视为真实电气冲突，而不是放宽验证。
10. 将 SWIO 画成悬空短线会触发官方“单网络仅连接一个元件引脚”警告；可制造原理图必须连接到已确认的真实下载排针或测试点，不能以网名代替物理接口。
11. 同一电气网络的多个分支若分别以相同显式网名创建，嘉立创EDA会在合并后报告“多个网络名”；应使用 `SCH_PrimitiveWire.create` 的多路径参数，在一次调用中创建整个分支网络。
12. DRC 面板保持打开时，连续 API 写入可能出现长时间无响应；重试前应关闭旧面板、只读确认空白基线和 DRC 空数组，并继续保留超时自动回滚。
