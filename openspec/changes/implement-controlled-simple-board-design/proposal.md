# Why

当前 Demo 已具备真实 AI 对话和嘉立创EDA连接检测，但仍只能做只读查询，无法把已确认的简单控制板需求安全地转换成可审查、可执行、可回读和可恢复的原理图修改。若直接开放任意脚本或无审批写入，会给用户工程带来不可追踪和不可恢复的风险，因此需要先建立一个范围固定的 P0 端到端闭环。

# What Changes

- 建立嘉立创EDA当前工程、文档、原理图页、元件、引脚、导线和网络标识的规范化只读模型，并保留原始证据与采集时间。
- 将 AI 对话收集到的需求转换为结构化工程计划；计划必须明确 MCU、电源、LED、按键的器件身份、连接关系、放置坐标、验证规则和风险，未知项不得自动猜测。
- 为计划生成稳定哈希，并由 Runtime 签发绑定目标窗口、目标文档、计划哈希和有效期的一次性人工批准令牌。
- 只开放白名单、类型化、可审计的原理图命令；禁止浏览器或 AI 向嘉立创EDA执行任意 JavaScript。
- 写入前通过嘉立创EDA文档源码接口建立真实快照；执行元件、导线和网络标识的固定写入后保存并回读验证。
- 失败时使用快照恢复目标文档并再次回读；所有阶段写入修改日志和结构化错误记录。
- 接入嘉立创EDA可用的官方 ERC 能力探测。只有真实官方 ERC 已执行且通过时才标记 ERC 通过；官方 API 不可用时明确阻塞，不以自定义检查冒充 ERC。
- 提供一个专用空白测试工程上的简单控制板端到端验收流程；不在本变更中自动布局 PCB、自动布线或导出生产文件。

# Capabilities

## New Capabilities

- `eda-design-read-model`: 从已选中的嘉立创EDA窗口读取并规范化当前设计上下文，支持证据化回读和目标漂移检测。
- `controlled-simple-board-planning`: 将简单控制板需求生成确定性的结构化计划、计划哈希、审批令牌和可审计状态机。
- `controlled-schematic-write-recovery`: 以白名单命令执行原理图写入、源码快照、保存、回读验证、官方 ERC 门禁和失败恢复。

# Impact

- Runtime：新增设计读取、计划生成/审批、执行编排、快照恢复、ERC 能力探测和审计接口。
- 前端：AI 页面展示结构化缺失信息与计划；EDA 页面增加目标选择、审批、执行、回读、ERC、回滚和错误详情。
- 嘉立创EDA桥接：由只读命令扩展为参数严格校验的固定命令注册表，不开放任意代码执行。
- 数据：扩展任务、审批、执行记录、快照元数据、修改日志和错误日志模型；API 密钥继续只由本机 Runtime 管理。
- 测试：增加哈希防篡改、目标漂移、令牌重放、快照/回滚、部分失败和端到端简单板流程测试。
