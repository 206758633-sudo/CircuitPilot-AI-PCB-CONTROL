# 正式导出 / 签核边界验证（2026-10-29）

> 结论：CircuitPilot 的正式生产导出仍**必须被人工门禁阻断**；AI 不签核、不下单、不付款。  
> 本轮只做边界核对，不尝试绕过，也没有生成正式生产文件。

## 1. 当前边界

- 生产导出走 `runtime/production-export.mjs` / release gate，要求证据闭合（A16 工程分析、在线 DFM、人工终审签核等）；缺失即 `blocked`，不生成可下单生产包。
- `cp_export` 是执行类工具，需要显式 `confirm=true` + `requestId`；即使用户批准执行计划，导出仍受 Runtime 放行门禁约束。
- 永久禁止：下单/付款、代替工程师签核、把 AI 结论当成正式放行。
- 临时/实验 EDA 适配器不是生产桥；导出验收不能基于“适配器看起来成功”。

## 2. 当前项目已知 block 依据（来自 Runtime 状态/问题清单）

- `RELEASE_FINAL_EXPORT_HUMAN_GATES`：正式生产文件被人工门禁挡住；建议先补 A16 工程分析，再由工厂/工程师做在线 DFM 与终审签核。
- 项目阶段显示“正式放行仍 block”；未收口问题仍存在。
- 回滚演练失败的安全事件尚未真机复验修复，不能作为正式放行依据。

## 3. 验证结论

| 项 | 状态 |
|---|---|
| 生产导出门禁存在且 fail-closed | 已有实现与回归（release-gate/production-export 测试）；未绕过 |
| AI 代替签核 | 禁止；无接口 |
| 下单/付款 | 永久禁止；capability matrix 标 unavailable |
| 正式导出已执行 | **否**；本项目仍被人工作业门禁 block |
| 导出证据 | 未生成正式导出证据；只有只读/Drc/回滚事故证据 |

## 4. 下一步（需要人）

1. 由工程师补齐 A16 工程分析、在线 DFM、终审签核。
2. 人工在 Runtime/UI 中确认放行门禁；AI 不能代为签核。
3. 放行后再由用户对具体导出计划确认；导出仍逐板、留 manifest/哈希/证据。
4. 在回滚可靠性真机复验前，不把任何“导出预检通过”宣传为可生产。

## 5. 非目标

- 不做“AI 自动签核”；
- 不做“批量一键导出绕过人工门禁”；
- 不在实验适配器上跑正式生产导出并当作验收。
