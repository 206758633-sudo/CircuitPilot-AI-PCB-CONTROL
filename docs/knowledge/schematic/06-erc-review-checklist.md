# ERC 与原理图评审：常见错误逐条处理、评审清单与证据要求

> **一句话结论**：ERC 的价值不在“跑出 0 错误”，而在**每一条告警都有明确归属**（已修 / 有依据的豁免 / 待复核），并且评审能拿出网表、计算、波形、datasheet 页码作为证据；被批量忽略的告警等于没跑。

## 适用范围与边界

| 项 | 内容 |
| --- | --- |
| 适用阶段 | 原理图完成 → ERC/DRC → 原理图评审 → 放行导出网表 |
| 输入 | 原理图源文件、ERC 报告、网表、BOM、需求/接口清单、datasheet |
| 输出 | ERC 处理记录（逐条）、评审问题单、放行结论与证据归档 |
| 不覆盖 | PCB DRC/DFM、EMC 实测、安规认证；这些是后续门禁 |
| 编号说明 | 本篇知识点编号为 **KP-SCH-091～109** |

> 说明：不同 EDA 的 ERC 报错文本不同（嘉立创EDA 专业版为“原理图 DRC/ERC 等效”检查）。本文按**错误类型**给判据与处理，实际报错文本以当前 EDA 输出为准；不确定时以网表和设计意图为准，不得只看告警文字。

## 一、ERC 判读总则

### KP-SCH-091 ERC 判读总则：分类、基线、豁免都要留痕

- **判据**：ERC 必须按“错误（Error）/ 警告（Warning）/ 信息”分类处理；每条告警必须有三种归属之一：**已修复、有依据的豁免（waiver）、待复核（open）**；豁免必须记录理由、依据、批准人与失效条件。默认状态是“未处理”，不是“通过”。
- **为什么**：ERC 告警数量多时，最省事的做法是“全部忽略”，而这正是漏掉真问题的路径；没有归属记录的 ERC 报告不能作为放行证据。
- **怎么做**：
  - 每次改图后重跑 ERC，保存报告（含时间/版本）。
  - 建一张 ERC 台账：编号、类型、对象（位号/网络）、判定、理由、依据、责任人、状态。
  - 对“设计上故意”的告警（如 NC、测试点、未用门）用 EDA 的 no-connect/豁免机制显式标记，而不是口头说明。
- **怎么查**：评审时抽查台账中 3 条豁免是否真有依据（datasheet 页码/计算/测试）；检查报告版本与原理图版本一致。不通过 → 退回补台账。

### KP-SCH-092 悬空引脚 / 未连接（Unconnected pin）

- **判据**：ERC 报“引脚未连接”时，必须区分：①真正漏连（必须修）；②故意不连（必须放 NC/打 X 并注明理由）；③测试点/预留（必须有标注与 BOM DNP 说明）。不允许有“无标注的悬空”。
- **为什么**：悬空引脚在网表里没有连接对象，评审和后续 EDA 检查都无法区分“忘了”和“故意”；CMOS 输入悬空还会导致功耗与噪声问题。
- **怎么做**：逐条打开报告定位到引脚；按 KP-SCH-017 的规则处理；对连接器/排针的备用脚统一放 NC；对 IC 的未用功能脚按 datasheet 处理。
- **怎么查**：处理后再跑 ERC，确认该条从“未连接”变为“无告警”或“显式 NC”；核对 NC 数量与 datasheet 未用脚数。不通过 → 继续处理或补豁免。

### KP-SCH-093 输出冲突 / 多驱动（Output conflict）

- **判据**：同一网络上有两个及以上输出（推挽）同时驱动即判错误；开漏/双向总线（I2C、部分数据总线）允许“线与”，但必须有上拉且同一时刻只有一个主动驱动；三态缓冲器使能不得同时有效。
- **为什么**：输出冲突会形成大电流直通，轻则数据错乱，重则烧 IO；这类问题在原理图上不容易看出（尤其多页层次图）。
- **怎么做**：定位冲突网络，检查是否有：两个 MCU 引脚接同一信号、双向缓冲器方向配置错、层次端口方向错、上电默认输出冲突。用串联电阻不能“修复”输出冲突，只能限流。开漏总线确认上拉与协议。
- **怎么查**：检查网络成员与每个成员的引脚电气类型；核对层次端口方向；改完后重跑 ERC 并做上电测试（测冲突点电流/波形）。不通过 → 改拓扑/改方向/加缓冲。

### KP-SCH-094 电源引脚未驱动（Power pin not driven）

- **判据**：ERC 报“电源引脚未被驱动”表示某电源网络只有电源输入脚、没有电源输出/电源符号来源；必须确认该网络的电源来源（稳压器输出、电源符号、连接器）确实存在且同网络名。
- **为什么**：这通常意味着网络名写错、电源符号缺失、或两个电源域被误接一起；忽略它可能让某个电源脚实际没有供电。
- **怎么做**：检查该网络是否有：稳压器/连接器输出、对应的电源符号（PWR_FLAG 类）、网络名拼写一致；若确实是外部供电，加电源符号或按 EDA 规定加“电源来源”标记；若两个域短接，拆开并修正。
- **怎么查**：用万用表/网表确认该网络实际连到电源；上电测该引脚电压；不通过 → 修网络或补电源符号。

### KP-SCH-095 单端网络（Net has only one pin）

- **判据**：一个网络只有一个引脚即判错误/警告；必须确认：是漏连（修）、是测试点/预留（补 TP 并标注）、还是被误删的连线（恢复）。
- **为什么**：单端网络在 PCB 上表现为一段孤立走线或孤立焊盘，通常意味着设计意图没实现；也可能是删除器件后残留的网络标签。
- **怎么做**：按网络名定位；删除无用网络标签；补全连接；测试点网络保留但加 TP 位号；预留功能用 0Ω/跳线或 NC 明确表达。
- **怎么查**：处理后重跑 ERC；导出网表检查是否有孤立网络；不通过 → 继续处理。

### KP-SCH-096 重复网络名 / 同名网络（Multiple net names / implicit short）

- **判据**：同一网络出现多个名字（别名）或不同网络被同名标签/电源符号短接，均判错误；跨页连接必须使用正确作用域的标签（见 KP-SCH-009/010）；电源网络名重复必须确认是否同一电压域。
- **为什么**：同名即连接是隐式行为，容易把不该连的网络短在一起（如两个不同页的 `EN`），也会让网表与设计意图不一致。
- **怎么做**：统一网络名，删除多余别名；检查全局标签/电源符号的作用域；对确实需要跨页的信号改用层次端口；电源域同名不同压必须改名。
- **怎么查**：ERC 的同名/多标签告警；导出网表检查网络成员是否跨页异常；不通过 → 改标签/改作用域。

### KP-SCH-097 输入引脚未驱动（Input pin not driven）

- **判据**：输入型引脚所在网络必须有一个明确的驱动源（输出脚、电源符号、连接器输入等）；若该网络只有输入脚，判错误；对开漏/无源网络用上拉提供确定电平。
- **为什么**：输入无驱动会浮空，导致随机翻转/功耗异常；在 ERC 里它常与“单端网络”同时出现。
- **怎么做**：补驱动源或上拉/下拉；确认连接器输入是否真的接到该网络；对可选功能用 0Ω 选择；对未用输入按 KP-SCH-050 接固定电平。
- **怎么查**：重跑 ERC；上电测该引脚电平；不通过 → 补驱动/上下拉。

### KP-SCH-098 引脚电气类型配置错误

- **判据**：符号引脚的电气类型（输入/输出/双向/无源/电源/开集）必须与器件真实行为一致；类型错会导致 ERC 误报或漏报（如把输出设成无源，就查不出输出冲突）。
- **为什么**：ERC 的规则全部基于引脚类型；库建错，ERC 就失去意义。
- **怎么做**：建库/改库时按 datasheet 定义类型；电源脚设 power input、稳压器输出设 power output；开漏总线设 open collector/open drain；不确定的（如复用 GPIO）按最严格类型或双向设置，并在评审中说明。
- **怎么查**：抽查关键器件（MCU、电源 IC、连接器、逻辑门）的引脚类型；修改库后重跑全项目 ERC。不通过 → 改库并复查。

### KP-SCH-099 总线与层次端口连接错误

- **判据**：总线成员缺失、总线名与成员不匹配、层次端口与 sheet pin 数量/名称/方向不一致，均判错误；跨页总线必须逐位对应，不得依赖顺序猜测。
- **为什么**：位序错、端口漏接会造成“部分信号通、部分不通”，在联调阶段极难定位。
- **怎么做**：按 KP-SCH-008 建总线命名与位序表；层次端口做名称-方向-数量三对照；总线展开后逐位核对；必要时用网络别名统一。
- **怎么查**：ERC 层次/总线检查；导出网表逐位对照；不通过 → 修正后重跑。

### KP-SCH-100 未用门 / NC 处理与 ERC

- **判据**：多门器件未用门必须显式处理（输入接固定电平、输出 NC），否则 ERC 会报悬空/未驱动；处理方式必须与 datasheet 一致（有的运放要求输入接中点，有的要求接 GND）。
- **为什么**：未用门处理不当会导致功耗、噪声、甚至自激；ERC 只是提示，不能替代 datasheet 判断。
- **怎么做**：按 KP-SCH-014 处理；在图上放 NC 符号与注释；对多单元器件在 BOM 中注明使用单元。
- **怎么查**：ERC 清零相关告警；实测待机电流；不通过 → 按 datasheet 调整。

## 二、专项检查（电源/复位/时钟/接口/保护）

### KP-SCH-101 电源与去耦专项检查

- **判据**：每个电源域有来源、有去耦、有测试点；每个 IC 电源脚有 100nF；VDDA/VREF 有独立滤波；电源网络名唯一且与电压一致；上电时序有定义；保护器件在正确位置。
- **为什么**：电源问题占样机故障的多数，且 ERC 通常查不出“去耦漏了/容值不对/域接错”。
- **怎么做**：对照电源树表逐域核对；统计电源脚/去耦数量；检查电源符号与网络名；核对上电时序与 PG 连接；逐项记录证据。
- **怎么查**：示波器测每域上电波形与纹波；负载瞬变测试；不通过 → 补去耦/改时序/改保护。

### KP-SCH-102 复位、时钟、BOOT 专项检查

- **判据**：复位有确定上电行为与手动复位；复位脉宽满足 datasheet；时钟源明确（内部 RC/晶振）且精度匹配接口；BOOT/模式引脚在复位采样时有确定电平；调试口可用。
- **为什么**：这三项是“能不能启动/能不能烧录”的核心，ERC 无法判断“复位脉宽够不够”“BOOT 默认值对不对”。
- **怎么做**：按 `03-mcu-minimal-system.md` 的 KP-SCH-037~053 逐项核对；记录复位波形、时钟频率、BOOT 电平、SWD 连接结果。
- **怎么查**：示波器测复位/时钟/BOOT；实际烧录与断点调试；不通过 → 改电路后复测。

### KP-SCH-103 接口专项检查（上拉/终端/ESD/电平）

- **判据**：I2C 有上拉且阻值在计算范围内；SPI 每个从机有独立 CS 且默认无效；UART TX/RX 交叉且电平匹配；USB 有 90Ω 差分与 ESD；Type-C CC 有 Rd/Rp；CAN/RS485 有终端与偏置；所有外露接口有 ESD；隔离接口有隔离电源与地。
- **为什么**：接口问题大多在“协议能跑但边界不对”时出现，必须在原理图阶段定死参数。
- **怎么做**：按接口契约表（KP-SCH-054）逐项核对；把上拉/终端/偏置阻值写进 BOM 或注释；记录计算过程。
- **怎么查**：示波器测总线波形与电平；总线扫描/误码测试；不通过 → 调参数/加保护。

### KP-SCH-104 保护与降额专项检查

- **判据**：每个外露接口与电源入口都有保护；TVS 的 VRWM/VCL 与后级绝对最大值匹配；保险丝/PTC 额定值与 I²t 协调；反接保护 Vgs 在范围内；电容/电感/二极管/连接器降额满足规则；保护器件靠近连接器且地回路短。
- **为什么**：保护与降额是“不出事时看不出、出事时全暴露”的项目，必须在评审阶段用计算和 datasheet 逐项确认。
- **怎么做**：按 `05-protection.md` 的清单逐项打勾；把计算（钳位、I²t、热耗、降额比）写进评审记录；标注“需实测”的项单独列表。
- **怎么查**：ESD/浪涌/反接/短路/高温测试；测试后复测器件；不通过 → 整改并重测。

### KP-SCH-105 可制造性与可测试性检查

- **判据**：位号唯一、BOM 字段完整（值/封装/耐压/精度/DNP）、每个封装有对应焊盘、测试点齐全且可接触、调试/烧录点不被遮挡、关键网络有 TP、连接器 pin 定义与线序一致、丝印位号不被焊盘遮挡（与 PCB 规则对齐）。
- **为什么**：原理图是 BOM/贴片/测试的源头；这里的疏漏会在产线变成停线、错料、无法测试。
- **怎么做**：导出 BOM 做唯一性与字段校验；对照封装库核对；按调试/测试计划核对 TP；与 PCB 规则 `SILK-05`（丝印不压焊盘）等对齐。
- **怎么查**：BOM 校验脚本/人工抽查；试产首件 FAI；不通过 → 补字段/补 TP/改封装。

### KP-SCH-106 评审问题单与关闭标准

- **判据**：评审发现的每个问题必须有：编号、位置（页/位号/网络）、问题描述、严重度（阻断/重要/建议）、整改方案、责任人、关闭证据；阻断级问题未关闭不得放行。
- **为什么**：没有编号和关闭证据的评审意见会“讨论完就忘”，下一版重复出现。
- **怎么做**：用统一模板维护问题单；整改后在原理图上标注变更并重跑 ERC；关闭时附证据（截图/波形/datasheet 页码）。
- **怎么查**：放行前逐条检查关闭状态；抽查 3 条关闭证据是否有效；不通过 → 继续整改。

## 三、走查方法与放行门禁

### KP-SCH-107 原理图走查方法（读图顺序与提问清单）

- **判据**：走查必须按固定顺序进行并有记录：①电源树与保护链；②MCU 最小系统；③时钟/复位/BOOT；④接口与总线；⑤可制造性/测试点；⑥ERC 台账。每一步用“提问清单”驱动，而不是随意翻页。
- **为什么**：固定顺序能保证覆盖度；随缘翻页必然漏项，尤其是跨页的电源和地。
- **怎么做**：
  - 电源：输入从哪来、每域谁供、峰值电流多少、保护在哪、上电顺序？
  - MCU：去耦够不够、复位脉宽多少、时钟精度多少、BOOT 默认值、SWD 可用吗？
  - 接口：电平/速率/终端/上拉/ESD/隔离逐项问。
  - 制造：位号/BOM/封装/TP/烧录点。
  - 每问必须有图上的位置或数据回答，答不出即记为问题。
- **怎么查**：走查记录与问题单一一对应；抽查未参与设计者按清单走查能否发现同类问题。不通过 → 补走查。

### KP-SCH-108 放行门禁：ERC + 评审 + 证据三件套

- **判据**：原理图放行必须同时满足：ERC 无未归属告警（错误清零、警告有豁免记录）；评审问题单阻断项全部关闭；证据归档完整（ERC 报告、网表、BOM、计算记录、关键波形、评审签字）。缺一不得导出网表交付 PCB。
- **为什么**：单看 ERC 会漏掉“ERC 查不出”的设计问题；单看评审会漏掉机器能查的连接错误；只有两者加证据才能形成可复核的放行结论。
- **怎么做**：建立放行检查表并签字；网表导出后与原理图版本绑定（含哈希/版本号）；变更后重新走门禁，不得“只改一处就不重跑”。
- **怎么查**：按检查表逐项核对；抽查网表与原理图一致性；不通过 → 退回。

### KP-SCH-109 常见“假通过”与复核方法

- **判据**：以下情况属于假通过，必须复核：ERC 全忽略；豁免无依据；只看了 ERC 没看网表；评审只看了 PDF 没看源文件；改了图没重跑 ERC；BOM 与原理图版本不一致；测试点未实际探测；“datasheet 上应该可以”但没查页码。
- **为什么**：这些假通过会让问题流到 PCB/试产阶段，代价成倍增加；而且它们看起来都“完成了流程”。
- **怎么做**：对每条假通过给出复核动作：重跑 ERC、导出网表比对、抽查 datasheet 页码、实测波形、版本对齐；复核记录与放行记录一起归档。
- **怎么查**：随机抽取一个模块做“从原理图到网表到 BOM 到测试点”的端到端复核；不通过 → 整批退回重走门禁。
