## 设计原理拆解：一、电源域与上电骨架

### KP-CASE-WARDROBE12-01 电源域按“噪声/电压/关断”三原则划分

- **判据**：整机至少划分 `3V3`（数字/射频）、`2V8`（摄像头模拟）、`AU_GND`（音频参考）、电池域四类；不同域之间用 LDO/Buck/磁珠/0Ω 隔离，并在原理图上用独立网络名标识。
- **为什么**：ESP32-S3 的射频突发、摄像头 MIPI/DVP 时钟、功放的大电流都会在电源/地上产生不同频谱的噪声；共用一个 3V3 会把噪声互相注入，尤其是摄像头 2.8V 模拟轨和音频地。
- **怎么做**：电池 → 充电/升压/降压 → 3V3 主域；3V3 经 LDO 或滤波得到 2V8 摄像头轨；音频模拟部分单独汇到 `AU_GND` 后单点接 GND；每域入口放 10µF + 100nF，IC 引脚旁放 100nF。
- **怎么查**：检查网络名是否独立、每域是否有独立去耦、AU_GND 是否只单点连接；上电顺序是否满足 ESP32 与摄像头/功放的时序要求。

### KP-CASE-WARDROBE12-02 电池采样用高阻分压 + 可选开关，避免长期漏电

- **判据**：`BAT_SAMPLE` 必须经分压（典型两只 100kΩ 级）进 ADC，分压比按 ADC 量程计算；长期待机产品应加 MOS 开关或大阻值分压，把静态漏电流控制在 µA 级。
- **为什么**：电池电压高于 ADC 量程，必须分压；分压电阻长期挂在电池上会持续耗电，1400mAh 电池对 100µA 级漏电也敏感。
- **怎么做**：`BAT+ → R_top → ADC → R_bottom → GND`；ADC 端加 100nF 滤波；需要省电时用 MCU GPIO 控制分压下臂或 PMOS 开关；校准用实测电压两点法。
- **怎么查**：算分压比与最大电压、测待机电流、做一次满电/低电两点校准；确认 ADC 输入不超过量程。

### KP-CASE-WARDROBE12-03 充电与升压拓扑必须与电池化学体系匹配

- **判据**：4.35V/4.4V 高压电池必须选支持对应截止电压的充电 IC（如 `IP2312-4V35` 这类后缀标明 4.35V 的型号）；升压/降压 IC 的输入范围、限流、效率要覆盖电池 3.0–4.4V 全区间。
- **为什么**：把 4.35V 电池按 4.2V 充会充不满；按 4.4V 充普通 4.2V 电池会过充。升压芯片在低压端输入电流大，电感和限流不足会掉压/过热。
- **怎么做**：充电 IC 的 `VBAT` 截止电压、充电电流（按电池容量 0.5C 左右）、NTC/温度保护逐项核对；升压电感饱和电流 ≥ 峰值输入电流；Type-C VBUS 入口加 TVS 与 P-MOS 防反接。
- **怎么查**：对照电池规格书核对截止电压/充电电流；满载测 VBUS/电池端压降与温升；做一次 0°C/45°C 充电测试（如产品要求）。

### KP-CASE-WARDROBE12-04 防反接与浪涌保护要放在“最靠近连接器”的位置

- **判据**：Type-C/电池/板间连接器的入口，保护器件顺序为：连接器 → TVS/ESD → 防反接 P-MOS/理想二极管 → 保险丝/PTC → 后级；保护器件的地回流必须短而宽。
- **为什么**：ESD/浪涌是共模事件，保护器件越靠近入口，残压和耦合到后级的能量越小；P-MOS 防反接在反接时承受全部电流，必须核对 Vgs 与 SOA。
- **怎么做**：VBUS 放 SMAJ5.0CA 类 TVS；P-MOS 栅极加稳压管/电阻限制 Vgs；电池入口加 PTC 或保险丝；板间线用低电容 TVS（<0.5pF 级）避免影响信号。
- **怎么查**：反接/插拔测试后芯片不损坏；TVS 钳位电压低于后级绝对最大额定；保护器件地引脚到连接器地平面阻抗足够低。

## 二、USB 拓扑：一颗 Type-C 如何兼顾充电、烧录、数据

### KP-CASE-WARDROBE12-05 USB HUB 把“下载/调试/数据”拆成独立下游口

- **判据**：整机只留一个 Type-C 时，若同时需要 USB-UART 烧录与 ESP32 原生 USB（CDC/JTAG），应使用 USB HUB（如 CH334F）把上行口分成两路下游：一路给 USB-UART 桥，一路给 MCU 原生 USB。
- **为什么**：ESP32-S3 的原生 USB 与 USB-UART 不能同时直接接同一个 Type-C；HUB 提供稳定的拓扑与端口电源管理，也让产线可以只用一个口完成烧录与功能测试。
- **怎么做**：Type-C D+/D- → HUB 上行；HUB 下行 1 → CH340K → ESP32 UART0（TX/RX 交叉）；HUB 下行 2 → ESP32 原生 USB；每个下游口加 ESD（低电容）；HUB 晶体按 datasheet 选型并靠近放置。
- **怎么查**：分别验证“串口下载”“原生 USB 识别”“充电”三种插线场景；确认 HUB 下游口供电与过流保护；测量 D+/D- 眼图或至少做误码/枚举压力测试。

### KP-CASE-WARDROBE12-06 USB 差分对按 90Ω 设计，ESD 器件放在连接器侧

- **判据**：USB 2.0 HS 差分对按 90Ω±10% 差分阻抗布线，全程同层/同参考，长度匹配；ESD 器件应放在连接器与 HUB/MCU 之间，结电容满足 HS 要求（通常 <1–2pF 级，按器件规格）。
- **为什么**：阻抗不连续会产生反射、眼图闭合；ESD 器件放在芯片侧会让浪涌先打芯片再被钳位，保护失效。
- **怎么做**：按叠层计算线宽/间距；DP/DM 并行、少过孔、不跨分割；ESD 器件地端多过孔到地平面；连接器外壳地与信号地按产品接地策略处理。
- **怎么查**：检查差分对是否跨分割、ESD 位置、结电容参数；用 USB 枚举压力测试与眼图/TDR 复核（有条件时）。

### KP-CASE-WARDROBE12-07 USB-C CC 下拉是“受电”身份的硬性条件

- **判据**：Sink 设备 CC1/CC2 必须各接一只 5.1kΩ±1% 到 GND，不能并联共用、不能只接一路、不能用 10kΩ 代替。
- **为什么**：C-to-C 线缆下，Source 通过 CC 检测 Sink 的 Rd 才输出 VBUS；Rd 错误会导致“A-to-C 能供电、C-to-C 不供电”。
- **怎么做**：两只 5.1kΩ 分别靠近 Type-C 的 CC1/CC2 引脚；CC 走线远离 VBUS/D+/D-；如用 PD 控制器，按控制器参考设计接 CC 与 VBUS 开关。
- **怎么查**：万用表测 CC1/CC2 对地电阻；用 C-to-C 线实测 VBUS；检查是否误把 CC 与 D+/D- 短接。

## 三、摄像头与音频：并行总线和模拟地

### KP-CASE-WARDROBE12-08 DVP 摄像头按“并行总线 + 独立模拟电源”设计

- **判据**：DVP 接口含 8 位数据 + PCLK/VSYNC/HREF/XCLK + I2C 控制 + 复位/电源控制；数据线建议串 22–33Ω 匹配电阻；摄像头 2.8V 模拟轨单独滤波，FPC 连接器 24P/0.5mm 需确认翻盖方向与补强。
- **为什么**：DVP 是单端并行总线，边沿快、线数多，容易串扰；摄像头模拟电源对噪声敏感，共用 3V3 会出横纹/噪点。
- **怎么做**：数据线等长（相对 PCLK 的建立/保持满足摄像头时序）、远离 RF 与开关电源；2V8 由 3V3 经 LDO/磁珠得到，入口 10µF + 100nF；FPC 座下方避免走线，翻盖开合空间留足。
- **怎么查**：读摄像头 ID、出图无横纹、长时间预览不花屏；检查 FPC 方向/补强、2V8 纹波、数据线串阻与参考地。

### KP-CASE-WARDROBE12-09 I2S 音频要区分“数字时钟域”和“模拟地参考”

- **判据**：I2S 的 MCK/BCK/WS/SD 按源端串联匹配（典型 22–33Ω），走线短且远离 RF；音频模拟部分（麦克风、功放输入、喇叭）汇到 `AU_GND`，单点接系统地；功放使能 `PA_EN` 要有默认电平（避免上电爆音）。
- **为什么**：I2S 时钟是高速数字信号，回流路径不连续会串到模拟端；功放是大电流负载，地电流会调制麦克风参考。
- **怎么做**：Codec/ADC 的模拟地与数字地按 datasheet 分区；`AU_GND` 用星点或 0Ω 连接；喇叭输出走线宽、成对/双绞，加 LC/磁珠滤波（D 类功放按 datasheet）；`PA_EN` 加下拉，上电默认静音。
- **怎么查**：播放/录音测试底噪与串音、功放满功率时麦克风底噪、上电/关机爆音；检查 AU_GND 是否单点、PA_EN 默认电平。

### KP-CASE-WARDROBE12-10 共享 I2C 总线要核对地址、上拉与总线电容

- **判据**：摄像头、音频 Codec、传感器共用 I2C 时，地址不得冲突；上拉电阻按 `Rp(max)=tr/(0.8473·Cb)` 与灌电流计算，总线电容（含 FPC/走线/器件）不超过协议上限（标准模式 400pF、快速模式按规范）。
- **为什么**：地址冲突会让某个器件永远不响应；上拉过弱导致上升沿变缓、通信失败，过强则灌电流超标。
- **怎么做**：列出所有 I2C 从机地址；用 2.2–4.7kΩ 级上拉（按速率/电容计算）；长 FPC 场景减少挂载或加缓冲器；SDA/SCL 远离 RF 与高速时钟。
- **怎么查**：I2C 扫描确认地址、示波器看上升沿与电平、长线场景做批量读写压力测试。

## 四、可迁移的设计经验

**做对的**
1. 用 HUB 把“单 Type-C”拆成下载/原生 USB 两路，产线与用户场景都受益。
2. 摄像头 2.8V 与音频 AU_GND 独立，避免整机噪声互串。
3. 板间/外设连接器统一选带防呆/带锁的型号，降低装配错误。

**妥协的**
1. 2 层/4 层与整机成本强相关，音频/摄像头的地分割只能在有限层数内折中。
2. 单 Type-C 方案增加了 HUB 与 ESD 器件，BOM 成本与故障点变多。

**反面教训**
1. 参考 PDF 与 BOM 版本不一致（如摄像头型号、器件位号差异），**任何“照参考图设计”的动作都必须先对齐版本**。
2. PDF 提取只判定 85/580 引脚，说明仅靠文本层/矢量层提取网表仍有大量两脚器件无法自动判定，**不能把“提取成功”当成“网表完整”**。
3. 若 CC 下拉、PA_EN 默认电平、BOOT 脚这些“小电阻”漏画，整机会表现为“充不了电/爆音/下载不了”，排查成本远高于设计成本。
