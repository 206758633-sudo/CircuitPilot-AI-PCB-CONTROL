# 22. AI 辅助布局的功能分区与"可读原理图"验收

> **来源**：内部评审会《10-28 PCB 布局与 AI 辅助设计讨论》（见 [会议转写与判读](../../hardware/参考文献-10-28-PCB布局与AI辅助设计讨论.md)）。
> **证据等级**：**D（内部经验，未做量产/仿真验证）**。本文只把会上可复述的工程经验转成可执行、可检查的条目；具体数值（间距、区域面积、层数）必须按器件 datasheet、板厂能力与实测复核，**不得把本文当硬门禁**。
> **定位**：回答"AI 生成的版图应该怎么分区、怎么算可读、怎么写回前先自检"；布局的通用依据链见 [`08-component-placement.md`](./08-component-placement.md)，布线规则见 [`03-placement-routing.md`](./03-placement-routing.md)。

**一句话结论**：AI 辅助布局不是"把器件塞进板框"，而是**先分功能区、再在区域内就近、最后人工复核**；原理图也不是"网表连通就算画完"，**标签/元件不重叠、人眼能读**才算交付。

## 1. 功能分区（会议 R3）

### 1.1 按"功能块"而不是按"器件类型"分区

- **判据**：每个功能块有明确的 `id / 名称 / 成员位号 / 区域（mm 矩形）`；同一器件只能属于一个块；块与块之间不重叠；块区域完整落在板框内。
- **为什么**：会上明确"像文章分章节一样"——整块板内容太多，按功能分章节后，AI 与人找件、评审、返修都更快；按"电阻电容归一堆"会让电源热环路、去耦回路被拉长。
- **怎么做**：典型块：`power-input / dc-dc / battery-management / mcu-digital / analog / interface-connector / rf-highspeed / mechanical-3d`。先放连接器与结构件，再放电源/电池，再放数字/模拟，最后放小件。CircuitPilot 用设计意图 `blocks` 表达（见 §4）。
- **怎么查**：块区域两两不重叠、块内器件都落在区域内、每个器件至少属于一个块（或显式标"未分区"）。

### 1.2 小件靠主芯片，别拉太远（会议 R4）

- **判据**：去耦/反馈/使能/保护等小件优先靠近其服务的芯片或连接器两侧；简单网络（两三个端点）应短；复杂/远距离网络（总线、跨区电源）单独走、单独评审。
- **为什么**：会上"尽可能往芯片两边去""小件不要搞太远""简单的连接就近、复杂的远连接单独处理"——本质是缩短高 di/dt 回路与敏感节点，降低寄生与耦合。
- **怎么做**：以共享小网络的权重（越少端点的网络权重越高）作为布局亲和度；GND/电源这类大网络不能把整板拉成一团。CircuitPilot 的 `netAffinity()` 已按 `1/(网络端点数-1)` 加权。
- **怎么查**：抽 10 个去耦/反馈件量到主芯片的距离；两三个端点的网络是否被拉成跨板长线；复杂网络是否有单独说明。

### 1.3 AI 在"约定区域"内调整，并保持相对位置（会议 R5）

- **判据**：用户先圈定区域（块区域或选中区域）；AI 只在该区域内移动器件；未被要求移动的器件保持相对位置/相对顺序；越界或移动幅度大时必须给出可读原因。
- **为什么**：会上强调"约定好这个区域""保持一定的位置，他自己去调整"——用户要的是**可控的微调**，不是 AI 把整板重排。
- **怎么做**：区域用矩形表达，锚点用"靠近当前坐标 + 高权重"表达；用户显式锚定优先于 AI 的亲和度。**不要声称"锁定绝对坐标"**，除非实现真的锁死。
- **怎么查**：对比写回前后器件位移分布；区域外位移应为 0；被移动件是否能解释（去耦更近、避免重叠等）。

## 2. 层数策略（会议 R7）

- **判据**：默认从 **2 层**起步；只有出现"需要完整地平面/电源平面、屏蔽敏感信号、跨分割无法收敛、BGA/细间距逃逸"等明确理由时才加内层；叠层或电源方案变化后，**主要功能验证（ERC/DRC/关键网络/电源纹波）必须重跑**。
- **为什么**：会上"两层一般……信号层……内部……屏蔽一下""加了电源之后，应该要重新做一次主要的功能"——层数是成本与性能的权衡，不是越多越好；加层/加电源会改变回流路径与验证前提。
- **怎么做**：把"为什么加层"写进叠层说明；加层后重跑验证并留下证据；不要把"4 层更稳"当默认结论。
- **怎么查**：叠层说明是否给出加层理由；加层前后的验证证据是否都在；是否出现"层数加了但验证还是旧的"。

## 3. 原理图可读性验收（会议 R1）

> 这是本次会议里**最具体的"CircuitPilot 画原理图问题"**：网络标签全部朝右，压到元件符号上。

| 检查项 | 判据 | 不通过时 |
|---|---|---|
| 标签朝向 | 标签从引脚向**远离元件主体**的方向展开：右/左/上/下四向可选，不允许全部固定朝右 | 写前审计标出重叠，重新选方向；真机复核后再写 |
| 标签 vs 元件 | 标签矩形与元件符号包围盒不重叠（留可读余量） | 不写或降级为 warning 并在 UI 明示 |
| 标签 vs 标签 | 同一区域相邻标签不互相压字 | 选替代方向/错位；不要靠缩小字号糊弄 |
| 元件 vs 元件 | 元件符号包围盒不重叠、不过密 | 走确定性布局重排，或人工调整 |
| 连线 | 导线不穿过无关引脚/元件；复杂网络单独处理 | 交给人工评审，不自动硬拉 |

- **为什么**：标签压元件会让评审者误读网络、增加返修风险；"能连通"不等于"能读、能审"。
- **怎么做**：写前用纯函数估计标签/元件矩形做碰撞打分（CircuitPilot：`runtime/schematic-layout.mjs`），写后仍以官方网表 + ERC 为准；**可读性审计是 warning，不替代电气验收**。
- **怎么查**：`auditSchematicReadability` 的重叠计数为 0；人工抽看截图；ERC/网表读回通过。

## 4. 与 CircuitPilot 实现的对应

| 能力 | 代码 / 接口 |
|---|---|
| 原理图标签朝向与防重叠 | `runtime/schematic-layout.mjs`（`planNetPortLabels`、`auditSchematicReadability`）→ `runtime/net-connect.mjs` / `runtime/schematic-repair.mjs` |
| 原理图元件自动布局 | `runtime/schematic-layout.mjs`（`layoutSchematicComponents`）→ `runtime/netlist.mjs` 的 `compileReviewedNetlist` |
| PCB 功能分区 / 区域约束 / 保持相对位置 | 设计意图 `blocks` → `runtime/engineering/functional-blocks.mjs` → `runtime/placement.mjs` 的 `planOutlinePlacement` |
| 分区图先出 | `POST /api/eda/pcb/placement/plan` 响应 `blockMap`（块 → 区域 → 成员 → 利用率） |
| 人工复核 ≥ 30 分钟 | 本文 §5 清单；实现只提供清单/证据，不代签 |

## 5. 人工复核清单（会议 R8：至少 30 分钟）

- [ ] 功能分区是否成立？块与块有没有把该近的拆开、把该隔离的放一起？
- [ ] 连接器/结构件/安装孔是否先定、开口朝外？
- [ ] 去耦/反馈/晶振/ESD 是否真的靠近目标器件（量距离，不凭感觉）？
- [ ] 电源热环路、地回流、跨分割是否有人看过？
- [ ] 简单网络是否短、复杂远网是否有说明？
- [ ] 层数/叠层理由是否写清；加层/加电源后验证是否重跑？
- [ ] 原理图标签/元件是否可读（无压字、无压件）？
- [ ] DRC/ERC 是否官方执行、结论是否落盘、失败项是否有处理记录？

> 时间要求是经验值（会上"至少半个小时"），不是标准条款；板越大/越高速，复核时间应更长。

## 6. 明确不进入规则的内容
