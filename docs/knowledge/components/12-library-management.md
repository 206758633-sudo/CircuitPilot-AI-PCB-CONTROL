# 元件库管理（符号 / 封装 / 焊盘 / IPC-7351 / 版本与审核 / BOM 一致性）

> **一句话结论**：EDA 库不是“画图用的素材”，而是**设计意图的唯一事实来源**：part（料号身份）、symbol（符号）、footprint（封装/焊盘）、3D 四层必须互相链接且可追溯；每个库必须经“datasheet 优先的三源核验 + 双人审核 + 首件验证”，焊盘必须按 IPC-7351 密度等级与器件公差计算，库版本与 BOM 必须双向一致——否则错误会在贴片、装配或量产后才暴露。

- **适用阶段**：选型 → 建库 → 原理图 → Layout → BOM/投产 → 变更维护。
- **适用对象**：原理图符号库、PCB 封装/焊盘库、3D 模型库、part/BOM 映射、替代料库与受控库管理流程。
- **可信等级**：本文为 `reference` 参考知识。IPC-7351 密度等级与焊盘公式、J-STD-020/J-STD-033（MSL）、JESD 系列**必须按标准原文与被选器件 datasheet 复核**；文中尺寸为说明用示例，不得当作可直接入库的数值。
- **严禁**：不得编造 LCSC 料号、器件型号、封装尺寸与引脚定义；不得把“通用封装尺寸”当作某颗器件的已核验 land pattern；未核验库不得进入生产库。

---

## 1. 库的分层与三源核验

### KP-CMP-194 库的四层模型：part / symbol / footprint / 3D 各自独立、互相链接

- **判据**：库必须拆成四层并建立链接：①part（MPN/LCSC/厂商/封装/生命周期/核验状态）；②symbol（引脚号、名称、电气类型、多 unit）；③footprint（焊盘/丝印/阻焊/3D 引用）；④3D 模型。任一层变更必须评估其余层是否受影响。
- **为什么**：把料号、符号、封装混成一个“器件条目”会导致改一层不知道其余层是否还匹配；EDA 库最常见的错误就是四层不同步。
- **怎么做**：按项目库结构定义字段与唯一键（part→symbol→footprint→3D）；替代料指向同一 footprint 时记录差异；用脚本检查断链。
- **怎么查**：四层链接完整性报告；变更记录是否覆盖四层；抽样打开任意 part 能否追到 datasheet 与 3D。
- **依据**：IPC-7351 对 land pattern 与器件封装的关系定义；公司 EDA 库管理规范（按项目工具链复核）。

### KP-CMP-195 三源核验：datasheet 第一优先，供应商次之，EDA 库最后

- **判据**：symbol/footprint/焊盘必须与器件 datasheet 的 Pin Configuration、Package Drawing、Recommended Land Pattern 一致；供应商页面用于交叉验证；EDA 自带库/第三方库只能作参考（可能来自旧版本或通用库）。
- **为什么**：EDA 库与供应商页面都可能滞后或出错；datasheet 是原厂设计依据，也是唯一能给出引脚定义与推荐焊盘的权威来源。
- **怎么做**：建库时记录 datasheet 版本/页码与三源核对结论；高风险器件（BGA/QFN/连接器/极性器件）双人复核；第三方库引入前抽检并登记来源。
- **怎么查**：核验记录与 datasheet 页码；Librarian/库检查脚本结论；首件通断与 AOI 结果。
- **依据**：Librarian 三源核验（EDA 库 / 供应商 / datasheet）；datasheet 为第一优先来源（按项目核验 SOP 复核）。

### KP-CMP-196 引脚映射与 Pin 1：符号引脚号必须等于封装焊盘号

- **判据**：符号引脚号/pin name、封装焊盘号、datasheet pin map 三者必须一致；Pin 1 位置（凹点、斜边、丝印、极性标记）在符号、封装、丝印与 3D 中一致；禁止“左上角就是 1”之类的默认假设。
- **为什么**：pin map 错会导致整颗反装或直通烧板；Pin 1 认错在 QFN/LQFP/BGA 上尤其致命，返修成本高且可能连带损坏焊盘。
- **怎么做**：建库时逐脚核对并截图留档；封装丝印标 Pin 1；极性器件（二极管、钽电容、LED、连接器）额外核对方向；首件用万用表/通断/体二极管测试验证。
- **怎么查**：三源核对表；首件测试记录；AOI 程序与丝印方向；返修/失效案例是否指向 pin 错。
- **依据**：器件 datasheet 的 Pin Configuration / Package Drawing；IPC-7351 对丝印与方向标识的建议（按标准复核）。

### KP-CMP-197 IPC-7351 密度等级 A/B/C：按产品与工艺选，同板统一

- **判据**：焊盘按 IPC-7351 密度等级选择：A（Most，最大焊盘，利于返修/高可靠/波峰焊）、B（Nominal，通用）、C（Least，最小，高密度）；等级决定 toe/heel/side 外延与 courtyard 尺寸；同一板同一封装族应统一等级。
- **为什么**：焊盘过大易桥连、占面积；过小易虚焊/立碑/强度不足；等级不统一会造成同一板工艺窗口不一致，良率波动。
- **怎么做**：项目开工确定等级（消费类常用 B/C，工业/高可靠常用 A/B）；库按等级参数化（同封装多等级变体）；courtyard 按等级留足并避免器件干涉。
- **怎么查**：焊盘尺寸与 IPC-7351 计算表对比；courtyard 与器件干涉检查；首件良率与立碑/桥连统计。
- **依据**：IPC-7351（Land Pattern 标准）的密度等级定义；具体数值按标准版本复核。

### KP-CMP-198 焊盘尺寸计算：基于引脚公差与工艺能力，禁止“通用尺寸”

- **判据**：焊盘长度/宽度 = 引脚尺寸 + toe/heel/side 外延（按 IPC-7351 与器件公差），并纳入贴片精度、锡膏量、阻焊限定、返修需求；连接器/功率器件优先采用 datasheet 推荐 land pattern。
- **为什么**：不同厂家同封装引脚公差可能不同（尤其连接器、功率器件、模块），套用“通用封装尺寸”会造成虚焊、桥连或机械强度不足。
- **怎么做**：用 IPC-7351 计算器/厂家推荐值，记录输入参数（引脚尺寸、公差、密度等级）；库中保存计算依据；高密度/细间距器件加钢网与 AOI 验证。
- **怎么查**：焊盘计算记录；切片/推力测试；首件 AOI/SPI；同类封装良率对比。
- **依据**：IPC-7351 焊盘计算公式与器件 datasheet 公差（按标准原文复核）。

### KP-CMP-199 散热焊盘 / 过孔 / 阻焊开窗：三件事一起定

- **判据**：EPAD/散热焊盘尺寸按 datasheet；过孔阵列（孔径、间距、是否塞孔、是否 via-in-pad）按热与工艺确定；阻焊开窗（SMD 或 NSMD 口径）按 IPC-7351 与 datasheet；钢网开孔按面积比与锡量设计。
- **为什么**：开窗与焊盘不匹配会造成漏锡、虚焊、散热不良；未塞孔的散热过孔会让锡膏流失，导致焊点空洞与强度不足。
- **怎么做**：EPAD 按 datasheet + 热计算确定过孔数量；BGA/QFN 区过孔塞孔；钢网对 EPAD 分区开孔控制锡量；返修方案提前考虑。
- **怎么查**：焊盘/开窗/过孔尺寸核对表；X-ray 空洞率；首件切片；热成像验证散热。
- **依据**：IPC-7351 开窗与 courtyard 建议；J-STD-001/IPC-A-610 对焊点空洞与润湿的验收要求（按标准版本复核）。

### KP-CMP-200 3D 模型与机械装配核对

- **判据**：每个库应有可用 3D 模型或明确“缺失/占位”标记；3D 的 Pin 1、本体尺寸、高度必须与 datasheet 一致；结构装配前必须做干涉检查（连接器、高器件、屏蔽罩、外壳）。
- **为什么**：缺 3D 或尺寸错会在结构装配阶段才暴露，返工成本高；连接器/高器件干涉是常见试产阻塞项。
- **怎么做**：建库同步 3D；标注高度与占位；与结构做干涉检查并留记录；无法提供 3D 的器件标“需结构确认”。
- **怎么查**：3D 完整性清单；装配干涉报告；首件实物高度核对。
- **依据**：器件 datasheet 的 Package Drawing（含高度/公差）；公司机械设计规范。

## 2. 版本、命名与审核

### KP-CMP-201 命名规范：族 + 尺寸 + 变体 + 极性 + 密度等级

- **判据**：footprint 命名必须包含封装族、尺寸/间距、变体（如引脚数）、极性/方向、密度等级；symbol 命名与 part 关联且唯一；禁止“新建封装1/复制副本”类命名。
- **为什么**：命名是检索与防错的第一道门；同名不同义、同义不同名会造成重复库与错用，且难以审计。
- **怎么做**：发布命名规范与模板；用正则/CI 检查；历史库按规范批量重命名并保留映射；替代/变体在名称中体现。
- **怎么查**：命名合规率扫描；重复库/近似库扫描；抽查命名与库内容是否一致。
- **依据**：IPC-7351 对封装族与 (公制/英制) 尺寸命名的约定（按标准复核）；公司库规范。

### KP-CMP-202 库版本管理：受控库 + 变更记录 + 已投产板快照

- **判据**：库必须版本化，任何变更升版本并记录“改了什么/为什么/谁改/影响哪些板/验证方式”；已投产板应冻结其使用的库版本或保存快照；禁止静默修改已发布库。
- **为什么**：库被静默修改会造成“同样的图，不同批次板不一致”，追溯与复现困难；已投产板可能因库变更导致钢网/AOI 不匹配。
- **怎么做**：受控库（Git/PLM/SVN）与发布标签；变更评审；BOM 记录库版本；旧版只读保留。
- **怎么查**：版本记录完整性；BOM-库版本映射；变更影响分析；旧项目能否复现。
- **依据**：公司配置管理/PLM 流程；ISO 9001 文件与变更控制要求（按认证范围复核）。

### KP-CMP-203 审核流程：四眼原则 + 首件验证

- **判据**：新建/修改库必须由建库人之外的第二人复核（四眼原则），核对 pin map、焊盘、Pin 1、3D 与命名；高风险封装（BGA/QFN/连接器/极性器件）加首件验证；审核记录留档。
- **为什么**：单人建库错误率高且难以自查；首件是贴片前最后一道拦截，成本远低于批量返工。
- **怎么做**：审核清单化（逐项打勾）；双签后入库；首件 AOI/X-ray/通断；问题回写库并复盘。
- **怎么查**：审核记录覆盖率；首件拦截率；库缺陷逃逸统计。
- **依据**：公司质量体系对设计评审/验证的要求；IPC-A-610 首件检验实践（按标准复核）。

### KP-CMP-204 EDA 库与 BOM 一致性：字段映射 + 双向核对

- **判据**：BOM 的 MPN、封装、位号必须能解析到库中唯一 part；封装名与库 footprint 一致（或存在受控映射表）；BOM 变更必须同步库与替代料信息。
- **为什么**：BOM 与库脱节会导致贴片错料、封装不符、采购错料；手工维护两份清单必然分叉。
- **怎么做**：BOM 模板带库 ID/封装字段；导入时校验；发布前跑双向核对脚本；差异清单人工确认。
- **怎么查**：BOM-库一致性报告；错料/换料记录；封装与库映射抽查。
- **依据**：公司 BOM 规范与 PLM/ERP 集成规则；IPC-2581 等数据交换标准可作为格式参考（按项目采用情况复核）。

### KP-CMP-205 库来源与授权：原厂/自建优先

- **判据**：优先使用原厂官方库或自建库；第三方库必须核验来源、版本与许可，并在引入前抽检；来源不明库不得用于生产。
- **为什么**：第三方库可能引脚、尺寸或焊盘错误，也可能存在许可限制；来源不明会让问题无法追溯。
- **怎么做**：库来源登记（来源/版本/许可/引入人）；抽检关键封装；建立“可信库清单”。
- **怎么查**：来源台账；抽检记录；许可合规文件。
- **依据**：原厂库发布说明；公司知识产权与采购合规制度。

### KP-CMP-206 库变更影响分析：覆盖已投产/在制板

- **判据**：库变更必须评估对已投产/在制板的影响：焊盘、丝印、钢网、AOI 程序、测试夹具、装配工艺；影响已投产板时冻结或走 ECN 变更流程。
- **为什么**：改库不改已投产文件会造成新旧板混线不良；钢网/AOI 不匹配会在产线才暴露。
- **怎么做**：变更影响清单；ECN/变更单；新旧版本并行期标识与隔离；产线通知。
- **怎么查**：ECN 记录；混线不良统计；钢网/AOI 版本与库版本对应。
- **依据**：公司 ECN/变更管理流程；ISO 9001 变更控制要求。

### KP-CMP-207 库测试与验证：试贴 / 首件 / 通断

- **判据**：新封装首次使用必须试贴（或首件）验证：贴装偏移、立碑、桥连、虚焊、极性、焊点强度；关键引脚做通断/体二极管测试；实测尺寸与 datasheet 一致。
- **为什么**：库错误只有实际贴装才充分暴露；试贴成本远低于批量返工，也能验证钢网/贴片程序。
- **怎么做**：试贴板覆盖代表封装；记录问题并回改库；把验证结果与库版本绑定；重复使用前复查历史问题。
- **怎么查**：试贴报告；首件 AOI/X-ray；库修正记录；同类封装良率趋势。
- **依据**：IPC-A-610 验收判据与公司首件流程（按标准版本复核）。

## 3. 一致性与运维

### KP-CMP-208 BOM → 库 → 封装 双向核对（料号/封装/符号/位号）

- **判据**：投板前执行双向核对：BOM 每行 → part → symbol → footprint；反向 footprint → 使用板/位号。任一方向不一致或断链 = blocked，必须修复或带理由批准。
- **为什么**：单向核对会漏“库里有但 BOM 没用”“封装被替换但 BOM 未更新”的隐患；双向才能闭环。
- **怎么做**：脚本化核对（字段/链接/封装名）；差异清单人工确认；结果进 release gate。
- **怎么查**：核对报告与差异闭环；投产前门禁记录；量产后错料事件复盘。
- **依据**：公司发布门禁与配置管理流程；可参考 IPC-2581/PLM 数据一致性实践（按项目复核）。

### KP-CMP-209 多工具/多团队库同步：唯一主库

- **判据**：使用多个 EDA（Altium/KiCad/其他）或多人协作时，必须有唯一主库与受控同步机制；禁止各自维护同名库；转换后的库必须重新核验（不能默认“转换正确”）。
- **为什么**：多库并存会产生版本分叉，合并时引脚/焊盘错误极难发现；跨工具转换常丢失焊盘/丝印/3D 信息。
- **怎么做**：主库+导出/转换流程；转换后抽样核验与首件；权限与发布流程；定期一致性扫描。
- **怎么查**：重复库统计；转换核验记录；跨工具 BOM 结果对比。
- **依据**：公司 EDA/PLM 工具链规范；IPC-2581 等交换格式（按采用情况复核）。

### KP-CMP-210 库废弃与迁移：deprecated 不删除

- **判据**：废弃库必须标记 deprecated + 替代指向 + 停用日期；已使用该库的板要评估迁移（是否必须重画/重核）；禁止直接删除库文件。
- **为什么**：直接删除会让旧项目无法打开、无法复现；替代指向能避免产线继续误用。
- **怎么做**：废弃流程与审批；保留只读快照；迁移记录（板号/位号/替代库）；通知使用方。
- **怎么查**：废弃清单；旧项目可复现性；误用 deprecated 库的检查。
- **依据**：公司配置管理流程；可追溯性要求（ISO 9001/IATF 16949 按认证范围复核）。

### KP-CMP-211 库质量指标与审计：用数据驱动改进

- **判据**：至少统计：库缺陷率（建库返工/首件拦截/量产错料）、审核覆盖率、命名合规率、BOM-库一致率；每季度审计并制定改进项。
- **为什么**：没有度量就无法改进；库质量直接影响直通率与返修成本，且问题往往跨项目重复出现。
- **怎么做**：指标看板；根因分析（按封装族/团队/工具）；培训与模板改进；把高发错误加入审核清单。
- **怎么查**：季度指标报告；审计记录；改进项闭环与效果对比。
- **依据**：公司质量目标与持续改进流程；IPC-7351/IPC-A-610 作为判据来源（按标准版本复核）。

## 4. 元件库评审清单（可直接勾选）

- [ ] 每个库是否按 part/symbol/footprint/3D 四层建链，且无断链？
- [ ] symbol 引脚号、footprint 焊盘号与 datasheet pin map 是否三者一致？
- [ ] Pin 1 在符号、封装丝印、3D 中是否一致，极性器件方向是否核对？
- [ ] 是否按 IPC-7351 密度等级建焊盘，且同板同封装族等级统一？
- [ ] 焊盘外延是否按引脚公差与工艺能力计算并留计算依据？
- [ ] EPAD/散热过孔/阻焊开窗/钢网开孔是否成套设计并验证？
- [ ] 3D 模型是否与 datasheet 尺寸一致，装配干涉是否检查？
- [ ] 命名是否符合“族+尺寸+变体+极性+密度等级”规范且无重复库？
- [ ] 库是否版本化、受控，已投产板是否记录库版本或快照？
- [ ] 新建/修改库是否经第二人复核，高风险封装是否做首件？
- [ ] BOM 与库是否做双向核对，差异是否闭环？
- [ ] 多工具/多团队是否有唯一主库与转换核验记录？
