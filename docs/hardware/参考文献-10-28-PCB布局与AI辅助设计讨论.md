## 二、判读（ASR 歧义点与置信度）

| 原文片段 | 判读 | 置信度 | 处理 |
|---|---|---|---|
| "所有的元器件都是充电有点严重，特别沉闷" | 应为"**重叠**有点严重，特别**拥挤/密**" | 中 | 作为需求 R2（元件/标签不得重叠、过密） |
| "网络标签都在朝向都是靠右的……元器件周边的网络标签它就会叠在元器件上面" | **网络标签统一朝右，压到元件符号上**（可读性缺陷） | 高 | 作为需求 R1（按引脚所在边朝外 + 标签间不互叠） |
| "分章节……资源分类……根据……原理去" | 版面/布局按**功能块分区**，像文章分章节 | 高 | 作为需求 R3（功能分区/区域图） |
| "这一块……空间的结构，半导体跟一些特殊的芯片……有3D……DCDC……电池管理" | 典型功能块：结构/3D、半导体/特殊芯片、DC-DC、电池管理 | 中 | R3 的块清单（可扩展，不写死） |
| "尽可能的往芯片的两边去……小件……不要搞太远" | 小元件靠主芯片两侧，不要拉太远 | 高 | 作为需求 R4（邻接/就近） |
| "简单的链接有……连那些复杂离得比较远的链接" | 简单网络就近，复杂/远距离连接单独处理 | 中 | R4（按网络复杂度/长度分开处理） |
| "约定好这个区域……保持一定的位置……他自己去调整" | 用户先圈定区域/约束，AI 在区域内调整，且保持相对位置 | 中高 | 作为需求 R5（区域 + 相对位置约束） |
| "第一步，原理图变成这个，然后把那个区域的图给出来" | 第一步先出**原理图 → 分区/区域布局图**，再执行写板 | 中高 | 作为需求 R6（先出分区布局图，后写回） |
| "两层一般要换原器件……信号层……内部……屏蔽一下，有一些信号" | 默认两层；信号/屏蔽/电源需要时加内层 | 中 | R7（层数策略：2 层基线，必要时加层） |
| "加了电源之后，应该要重新做一次，主要的功能" | 增加电源块后要重做主要功能验证 | 中 | R7（叠层/电源变化 → 重跑验证） |
| "人工审核……至少得半个小时" | 人工审核 ≥ 30 分钟 | 高 | R8（人工复核时长/清单） |
| "包括他们这个高频的需要" | 高频/高速需要单独规则 | 中 | R9（高频/高速分组与规则） |
| "至少先功能起来就可以了" | MVP：先跑通功能，再追完美 | 高 | 实施策略：先确定性可运行 |
| "B的重复……乘以3倍" / "安装门店" / "股票" / "村里的变化" | 与 PCB 无关或语义不可用 | 低 | **不作为需求** |

## 三、可落地需求（会议 → CircuitPilot）

| ID | 需求 | 落点 |
|---|---|---|
| R1 | **网络标签可读性**：标签朝向按引脚所在边朝外（右/左/上/下可配），标签之间、标签与元件符号不得重叠；写前能审计出来 | 原理图写入链路（net port / repair / netlist 布局）+ `schematic-layout` 纯函数 + 单测 |
| R2 | **元件平面布局不重叠**：按器件规模/类别分配格位，禁止压叠/过密 | `compileReviewedNetlist` 的固定 4 列网格改为确定性布局 |
| R3 | **功能分区**：DC-DC、电池管理、特殊芯片/模块、结构/3D、高频等成块占区；每块有区域与成员清单 | PCB 布局设计意图新增 `blocks`，自动布局按块区域落位 |
| R4 | **就近**：小件靠主芯片/连接器，简单网络短、复杂远网单独处理 | 复用电气亲和度（affinity）并把块内成员权重传下去 |
| R5 | **区域 + 保持相对位置**：用户圈定区域后 AI 只在区域内微调，尽量保持原相对位置；越界/不合理解释原因 | 设计意图新增 `blocks[].region` + 保持原位的锚定权重 |
| R6 | **先出分区图**：布局计划先返回"分区/区域图"（块 → 区域 → 成员），再允许写回 | 布局计划响应新增 `blockMap`，UI 展示 |
| R7 | **层数策略**：默认 2 层，需要屏蔽/电源平面再加内层；加电源后重做主要功能验证 | 文档/知识库 + 布局前提示（不改现有多层能力） |
| R8 | **人工复核 ≥ 30 分钟**：给可勾选的复核清单与耗时提示 | 知识库 + 复核文档（不伪造自动签核） |
| R9 | **高频/高速**：高速组、阻抗、包地、跨分割等单独成块/成组 | 复用 `highSpeed` 设计意图，并在功能分区里给高速块留区 |

> 边界：会议中"B 重复 ×3""安装门店"等表述不能还原为工程约束，**不进入需求**；所有新增规则只做确定性可测的落点，不伪造"AI 已审核"。
