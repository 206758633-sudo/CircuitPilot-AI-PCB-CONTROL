## 2. 方法

### 2.1 文本层（主证据，用于 U1 与网络标签）

1. `pdftotext -bbox` 输出 word 级坐标，用 `xml.etree` 解析（仅 stdlib，无第三方库）。
2. **U1(ESP32) 引脚表**：PDF 中该符号为“引脚号列—引脚名列—网络标签列”三列结构，同一行的 y 坐标严格对齐：
   - 左侧引脚 1–14：引脚号列 `x≈471.6`（两位数为 `x≈468.7`）、引脚名列 `x≈477.5`、网络标签列 `x≈420.8`（左对齐）；
   - 右侧引脚 27–41：引脚号列 `x≈583.2`、引脚名列 `x≈566–572`、网络标签列 `x≈593.6`（左对齐）；
   - 底部引脚 15–26：文字旋转 90°，引脚号 `y≈713.8`，网络标签以引脚 x 为中心（`cx` 对齐，偏差 ≤1.1pt）；
   - 判定规则：引脚号 y 与网络标签 y 之差 ≤1.6pt 即配对；引脚名与清单 `/tmp/sch_inventory.json` 的 `num→name` 完全一致（41/41 校验通过）。
3. 页 2（音频页）的 MediaBox 为 **848.88×600.48**，与页 1（1198.08×974.52）不同；坐标按页分别换算，否则整页错位。

### 2.2 矢量层（补充证据，用于其他 IC 的引脚→网络）

PDF 内容流（`jsPDF` 生成）**未压缩**，可直接解析：

- 走线：stroke 颜色 `(0, 0.53, 0)`（KiCad 绿）；
- 引脚 stub：stroke 颜色 `(0.53, 0, 0)`、长度 **7.2pt** 的短线，其外侧端点即引脚电气连接点；
- 元件外框：`(0.63, 0, 0)`；页面/TITLE 框：灰色 `(0.6,0.6,0.6)`。

处理流程：① 提取所有绿色线段并做 DSU 并查集（端点相接 + 端点在另一线段上 = T 型结）；② 对每个红色 7.2pt stub，取距其外端最近的绿色线段所在连通分量；③ 将文字（网络标签）按其包围盒底边/右边贴到最近的绿色线段，得到该标签所属连通分量；④ 引脚 stub 通过其附近 9pt 内的引脚号文本 →（位号，引脚号），位号候选需与清单中该位号的引脚编号集合相容，取最近者。

**该矢量方法在 U1 上做了盲测校验**：矢量法独立得到 U1 的 16 个带标签信号引脚，与文本表逐脚 100% 一致（见 §5），因此对 U4/U5/U8 等给予 high。

### 2.3 置信度定义

| 级别 | 含义 |
|---|---|
| high | 两条独立证据一致（文本列对齐 + 矢量连通），或文本表结构严格对齐且引脚名与清单一致 |
| medium | 单条证据明确（矢量连通+唯一标签；或引脚功能名 GND/VSS 判定；或 U1 电源引脚名）|
| low | 仅有间接线索；本次没有任何 pin 级 low（两脚无源件一律进 unassignedPins，不伪造 pin 级 low）|

# 第二轮：矢量连通图全量网表（task-3）

第一轮（task-1）只输出"有网络标签"的 40 个网络（85 引脚）。本轮改为**不依赖标签邻近**：以 PDF 内容流的矢量几何为唯一依据，重建**完整 pin 级网表**，标签只用于命名。

## 1. 方法（可复现）

1. 解析两页内容流（未压缩，jsPDF 生成），把每个路径按其**当前变换矩阵**（`q/cm/Q`）换算成 PDF 绝对坐标后拆成线段。
2. 先做全量线段**颜色/线宽统计**（见 §2），据此把线段分成四类：走线（绿）、引脚 stub（红短线）、符号图形（深红）、no-connect X（浅绿）。
3. **引脚 stub 建模**：每条红色短线就是某器件的一个引脚。stub 两端中，与绿色走线端点（或 X 标记中心）重合的一端为**外端**（电气连接点），另一端为**内端**（符号本体侧）——不再用"距数字远近"猜测方向，这是本轮相对第一轮的关键修正（第一轮 U1 底部 15–26 脚因此丢失）。
4. **引脚归属**：每个 stub 先按"最近引脚编号文字（<8.5pt，支持旋转文字）"确定 pin 号，再用**符号本体接触法**定器件：stub 内端落在哪个符号图形（深红 0.63）的边界上，该符号附近的位号文字即 ref；最后用"pin 号必须存在于该 ref 的引脚表"做一致性约束，并以全局贪心唯一分配（每个 (ref,pin) 只占一个 stub）。
5. **网络连通**：以绿色走线为边、线段端点为节点做并查集（端点重合 0.5pt 容差；T 型接点=端点落在另一线段中部），再把每个 stub 的外端点并入所在走线分量 → 一个连通分量 = 一个网络。同名标签的多个分量合并为同一网络（GND、3V3 等跨区域电源）。
6. **命名**：分量内有网络标签文字（文字 bbox 边距 <2.6pt 贴走线；电源符号的 GND/3V3 值文字取距其引脚 <13pt）→ 用标签名；无标签 → `N$<序号>` 且 `named=false`。

## 9. 局限与正确用法

1. 两脚无源件的 **pin1/pin2 方向**是几何约定（竖直取上=1、水平取左=1；KiCad 默认符号方向），无法从 PDF 文字验证；比对时请把两脚件网络按**无序**处理，或在有 kicad_sch/pcb 时用真实网表覆盖。
2. 无引脚编号文字的符号（Q2/Q16 SI2305、LED5 WS2812、SW2、U3）与清单中不存在的位号，未做 pin 级推断（禁止编造）。
3. 网络名优先取 PDF 标签文字；标签缺失时用 `N$xxx`，不代表设计者原本的 net 名。
4. 全部结果可复现：脚本 `/tmp/netx/round2final.py`（依赖 `/tmp/netx/r2.py`、`extract.py`），仅用 Python 标准库 `xml.etree`，未调用任何 EDA/bridge、未修改板文件。
