# 任务清单：CircuitPilot 通用 PCB 设计能力（含知识库与 4 个 Agent）

> 目标锚点见 `goal-circuitpilot-pcb-capability.md`：提升 CircuitPilot 自身能力，测试板只作验收样本。
> 本清单把工作拆成 7 条工作流（Workstream），每条都有独立验收；不包含“为某块板写死逻辑”的任务。

## 工作流总览

| WS | 主题 | 目标 | 预计 | ✅ |
|---|---|---|---|
| W1 | 联网检索基础 | AI 能查公网资料（已起步） | 2~3 天 | ✅ |
| W2 | 规格与数据契约 | design-spec、证据契约、回归 fixture | 3~4 天 | ✅ |
| W3 | **知识库（搭建/采集/加工/检索/审核）** | 可验证的工程知识库 K0→K1 | 1~1.5 周 | ✅ |
| W4 | **4 个 Agent + Orchestrator** | 独立取证、不自证、可复跑 | 1.5~2 周 | ✅ |
| W5 | 门禁与证据 | G1~G6 硬门禁 + 证据绑定 | 3~4 天 | ✅ |
| W6 | 编排与界面 | 验证中心、多板工作流 | 1 周 | ✅ |
| W7 | 实证与发布 | ≥2 块新板盲测、安装版、文档 | 1 周 | ✅ |

## W4 四个 Agent + Orchestrator

### W4-01 Netlist Auditor（网表审计）
- 输入：design-spec 意图网表 + EDA 实际网表（任意板）
- 输出：`netlist-diff.json`（missing/extra/pinMismatch/floating/gndEmpty/powerMixed，逐条 ref.pin）
- 要求：只读、逐条可定位、绑定 pcbUuid
- 验收：任意板可跑；缺陷可复现；单测覆盖 diff 规则 **状态：✅**

### W4-02 Rule Runner（规则执行）
- 输入：ERC/DRC/铺铜/规则与叠层一致性
- 输出：`rules-evidence.json`（违规明细/豁免/规则版本/运行时间）
- 要求：复用 `erc.mjs`/`drc.mjs`；未解释违规=阻断
- 验收：ERC/DRC 证据齐全；豁免必须有理由 **状态：✅**

### W4-03 Librarian（器件核验）
- 输入：BOM/器件清单
- 输出：`lib-evidence.json`（symbol/footprint/3D/引脚/替代料/生命周期，三源交叉）
- 要求：EDA 库（权威）→ JLC → datasheet（参考）；缺失/冲突判 `ambiguous`；EDA 库采集已真机验证（既有会话已登录，无需额外协助）
- 验收：每颗料号有证据；冲突显性化；降级模式可用 **状态：✅**

### W4-04 Field Loop（样机回归）
- 输入：样机/产测数据、门禁失败、问题单
- 输出：`field-issue.json` + 回归用例（关联 fixture/知识库条目）
- 要求：手动入口先可用，后续自动回灌；问题→根因→回归闭环
- 验收：至少 3 个历史缺陷转成回归用例 **状态：✅**

### W4-05 Orchestrator（编排，非审计 agent）
- 串 `spec → librarian → plan → netlist → auditor → rule-runner → gate`
- 失败自动回传修复并复验；**不掌握放行权**
- 验收：一键跑通；失败可复现；超时/部分失败语义明确

### W4-06 Agent 共性契约
- 只读取证、不得自证、证据带 fingerprint/digest、超时与失败语义、单测 + 故障注入
- 验收：4 个 agent 契约一致，审计日志可追溯
