# AI-PCBA 真实生产控制修复记录（2026-08-25）

## 目标

将“PCB能力矩阵”从只展示状态修复为可在操作系统内完成真实目标读取、固定计划编译、结构校验、一次性批准、受控执行、源码回读、官方PCB DRC和失败恢复的闭环。所有Beta图元能力仍必须人工复核，禁止把模拟响应标记为生产通过。

## 本次发现与修复

1. **High：前端缺失真实PCB执行入口**
   - 原因：Runtime已有`/api/pcb/context`、`plan`、`approve`、`execute`，但`EdaPage`只显示能力矩阵。
   - 修复：新增“PCB真实读取、审批与执行”工作区，提供读取、编译、校验、批准、执行五步操作及回读/DRC/恢复证据。

2. **Critical：PCB恢复没有保存与摘要验证闭环**
   - 原因：异常时调用源码恢复后直接读取，未强制保存；恢复失败后也没有锁死后续写入。
   - 修复：恢复后强制`pcb.save`，重新读取源码并比对规范化SHA-256；任何恢复失败都会进入`rollback_failed`并锁定后续PCB写入，直到人工检查并重启Runtime。

3. **High：执行成功缺少完整PCB回读证据**
   - 修复：执行后重新读取真实PCB上下文和源码，记录器件、走线、过孔、覆铜数量、目标指纹和源码摘要；官方DRC没有返回数组时不再误判为零错误。

4. **Medium：并发写入没有互斥**
   - 修复：新增运行中互斥，第二个PCB写任务返回`PCB_EXECUTION_BUSY`。

5. **Medium：界面仍显示“真实写命令尚未开放/只含只读命令”**
   - 修复：调整为“计划校验与一次性批准后允许”，真实写权限按Runtime、Bridge及暂停状态显示。

6. **High：PCB 3D预览被误当作PCB编辑器，图元读取返回500**
   - 根因：活动文档`documentType=15`实际为PCB 3D预览；同时PCB类实例不能直接通过Bridge JSON序列化。
   - 修复：新增`documentType=3`硬门禁；新增固定`pcb.open`导航入口；图元回读使用官方`getAllPrimitiveId()`，层和规则只返回显式可序列化字段。

## 仍然阻断“全自动量产”的事项

- Codex尚未生成完整、证据约束的PCB语义计划；目前CH32V003编译器只提供板框/导入/已有器件位置操作骨架。
- 自动布局规则、关键网络布线、完整过孔/覆铜/丝印生成和质量评分尚未固化为通用算法。
- BOM/CPL/Gerber/钻孔/3D虽已为当前CH32V003工程真实生成，但尚未在操作系统UI中形成独立批准、下载和不可变生产Manifest闭环。
- 嘉立创EDA处于半离线时DFM无结果，不能标记DFM通过。
- Tauri壳层尚未完成Node Sidecar打包、Apple签名和公证；当前可运行的是本地Web控制系统。

## 成功经验总结

- “测试全绿”不等于生产链路完整，必须逐端点追踪到实际页面入口和真实Bridge回读。
- PCB写入必须把一次性批准、源码快照、目标指纹、保存、回读、官方DRC、恢复保存和恢复摘要验证作为一个不可拆分事务。
- 官方Beta API可以受控使用，但其结果不能单独成为量产放行证据；必须结合回读、文件校验、人工机械复核和DFM。
