## 二、三条路线（方案 A / B / C）

| 方案 | 做法 | 能满足什么 | 代价 | 风险 | 建议 |
|---|---|---|---|---|---|
| **A. PCB 直建（现状延续）** | 继续用 EDA 原生 API 批量落件 + `pcb.line.create` 落网 + 自动布线器 + DRC 迭代 | ①✓ ②部分（网络只在 PCB 铜层）③可行 ④✓ | 机时 + 迭代轮次 | **无原理图背书** ⇒ ERC/网表错难清 ✗；不满足「AI 画图」✗ | 作为**保底干线** |
| **B. 原理图优先重建** | 在 Board1_1 逐页重建原理图（器件+连线+网名）→ 由原理图生成网表 → 同步 PCB | ①✓ ②✓（有网表源）③更易 ④✓ **且符合产品原设计流程** ✓ | **最大** ✗（原理图器件注入必须带 `Symbol`/`Device` 文档内属性，无法离线合成 ✗ ⇒ 需逐件经 EDA 放置通道，慢且有 abort ✗） | 工期不可控 ✗ | 仅在「必须有原理图交付物」时选 |
| **C. 混合（推荐 ✓）** | ①用 A 的配方补齐落件；②**AI 通道只负责「网表 + 规则生成」**（补齐绑定/引脚证据解开 `netlist/ai`），落网与布线用 EDA 原生（含自动布线器）；③DRC 迭代到 0；④ERC + 放行 | ①✓ ②✓ ③可行 ④✓，且**全程可留痕、可回滚** | 中等 | AI 通道若仍 blocked ⇒ 退化为 A，并把网表标注为**工程判断** ✓ | **首选** |
